# v1.5.0：仅渲染阅读模式与 PDF 导出更新

## 使用

- 工具栏“仅编辑”（⌘1）：隐藏右侧预览。
- “双栏”（⌘2）：源码与预览并排，仍可启用渲染编辑。
- “仅渲染”（⌘3）：隐藏左侧源码，正文只读；阅读滚动不再被隐藏的编辑区位置重置。
- 显示模式会记住，切换模式不修改 Markdown 内容。
- ⌘P：在文档窗口内依次显示风格/字号设置与保存面板；风格和字号会记住。导出时底栏显示进度，可取消。
- 导出完成后显示结果与“打开 PDF”按钮；未保存提醒不会再遮住导出成功信息。

## 导出改动

旧版依赖系统打印任务和主窗口状态。独立测试能够运行旧引擎，但未复现用户所遇到的具体失败；本次同时移除了这两个脆弱依赖：

1. 设置与保存改为异步文档附属面板，不再串联阻塞整个应用的模态循环。
2. 直接使用 WebKit PDF API，生成可选择文字的矢量内容，不调用系统打印任务，不要求渲染器持有编辑窗口。
3. 以真实 pt 字号排版，按段落、表格行和文字行边界分成 A4；捕获整个文档，而非当前屏幕区域。
4. 保留可点击链接、本地图片、中文与公式。为所有页面明确绘制风格背景，并裁剪到内容区域，避免边界溢出。
5. 支持进度、取消、超时与 WebKit 异常恢复；验证 PDF 后原子写入，取消或失败不破坏已有输出。
6. 导出代码分离到 `Sources/PDFExporter.swift`；测试使用生产实现，不再仅以源码字符串判断导出是否可用。

## 实际验证（本机 macOS 26.5.2 / Apple Silicon）

- 文件读写：30 项检查通过。
- 文档模型、模式状态、设置记忆和分页边界：40 项检查通过。
- 实际 WebKit / PDF / 原生面板 / SwiftUI 视图集成：378 项检查通过，运行于带实际资源的已签名 `.app` 测试包内。
- 四种 PDF 风格均实际生成；65 节长文导出 23 页 A4，首尾标记与全部章节完整。
- 80 行表格、90 行代码和超长段落完整；空文档可导出；中文/空格路径的本地图片可加载，PDF 链接可点击。
- 取消、超时、无效后缀和不可写目标能恢复状态，不覆盖原输出。
- 在隔离的原生面板中验证字号、风格、“继续”、“取消”和保存面板衔接。系统远程保存对话框的真实确认点击未自动化；收到目标 URL 后的完整生成/写入路径已实际执行。
- 实例化三种 SwiftUI 显示模式，检查编辑区/预览区是否存在及实际宽度；仅渲染占满内容宽度、没有源码输入框，网页正文确认为只读。另检查 WebKit 阅读快照和 PDF 首/中/末页、深色页、跨页表格的渲染图像。

macOS 14 和 Intel 硬件没有实机验证。此版本按行分页会延续长表格，不自动重复每页表头。

## 运行验证

```zsh
./scripts/test.sh
./build-app.sh
```

如需保留测试 PDF 与视图快照，首次使用空目录：

```zsh
MARKDOWNSTUDIO_PDF_TEST_OUTPUT=/tmp/markdownstudio-my-qa ./scripts/test.sh
```

测试输出目录带所有权标记，允许重复运行；不会往普通非空目录写入同名测试文件。
